# پیکرهٔ ChatML آمادهٔ فاین‌تیون — Carin-8B

قالب هر خط: JSON استاندارد با سه نقش `system` / `user` / `assistant` (سازگار با ChatML و Unsloth / Qwen3-8B).

```json
{"messages":[{"role":"system","content":"تو Carin-8B هستی؛ ..."},{"role":"user","content":"..."},{"role":"assistant","content":"..."}]}
```

## فایل‌ها
| فایل | نمونه | توضیح |
|---|---|---|
| `train.jsonl` | ۱۶٬۰۷۸ | آموزش |
| `validation.jsonl` | ۱٬۹۲۷ | اعتبارسنجی |
| `test.jsonl` | ۲٬۰۰۱ | آزمون |

جمع: **۲۰٬۰۰۶ نمونه** (دقیقاً ۸۰/۱۰/۱۰).

## منابع نمونه‌ها
| منبع | نمونه |
|---|---|
| پایه‌های تحلیلی (six-level foundations) | ۵٬۵۹۵ |
| ۱۰ نقش مدیریتی هلدینگ معدنی | ۸٬۴۰۵ |
| ۵ سمت خرده‌فروشی (نسخهٔ ۲ — هزار سناریوی یکتا در هر سمت) | ۵٬۰۰۰ |
| نمونه‌های هویتی Carin | ۶ |

## تبدیل از پیکرهٔ خام (خط قرمزها حفظ شده)
- `analysis_summary` و `hypothesis_testing` → پیام `assistant` (استدلال شفاف)
- `tool_call` / `data_request` → پیام `assistant` با متن «برای پاسخ دقیق، این داده را استخراج می‌کنم» + بلوک json
- `observation` → پیام `user` با متن «نتیجهٔ داده» + بلوک json (بدون نقش `tool`)
- `final` → پیام `assistant` قالب‌بندی‌شده: یافته / شواهد / ریشهٔ اصلی / اثر بر کسب‌وکار / اقدام پیشنهادی / اطمینان و محدودیت‌ها
- کاتالوگ داده‌ها و متریک‌ها (`available_context`) به انتهای پیام اول `user` چسبیده است تا مدل خارج از آن عدد اختراع نکند.
- نمونه‌های منفی عمداً وارد آموزش نشده‌اند.
- نمونه‌های تقریباً یکسان (پاسخ تکراری با همان سؤال) حذف شده‌اند — عمدتاً از پیکرهٔ خرده‌فروشی که فقط ۲۴ تا ۳۲ سناریوی یکتا در هر سمت داشت.

## نکته دربارهٔ پیکرهٔ خرده‌فروشی
نسخهٔ اول تولیدکنندهٔ خرده‌فروشی سناریوها را از فهرست کوچک تکرار می‌کرد (فقط ۲۴ تا ۳۲ سناریوی یکتا در هر سمت). در نسخهٔ ۲ (`tools/gen_retail_v2_part1.py` و `gen_retail_v2_part2.py`) همهٔ اعداد از مولد تصادفیِ همان نمونه می‌آیند و هر سمت واقعاً ۱٬۰۰۰ سناریوی یکتا دارد (کنترل یکتایی در خود تولیدکننده assert شده است).

نکتهٔ باقی‌مانده: در پیکره‌های قدیمی‌تر (پایه‌ها و هلدینگ معدنی) حدود ۱٬۰۰۰ نمونهٔ تقریباً تکراری وجود داشت که مبدل حذف کرده است — بازسازی آنها یک کار جداگانه است.
